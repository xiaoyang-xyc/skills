## 1. 成立性预审三问

在审证据之前先问三个问题，任何一个答"是"，漏洞可能根本不成立，直接出具"暂缓/放弃"判定：

### 1.1 数据公开性问：泄露的数据本来公开吗？
- 用搜索引擎抽查报告中的样本数据（电话、地址、编号、文件名）。
- 查目标官网是否有公开栏目展示同类数据（"服务电话""联系我们""网点查询"）。
- 案例教训：营业部对外服务电话在官网和第三方汇总站公开多年 → "未授权接口返回公开电话"不成立，属设计使然的公开功能。**公开数据 + 公开功能 = 无漏洞**。
- 反证成立条件：证明接口返回的内容**超出**公开页面所展示的范围（内部备注、未公开记录、原始库表字段）。

### 1.2 设计意图问：接口本来就是给匿名用户用的吗？
- 检查前端页面是否匿名可访问：页面匿名可见且展示同样数据 → 接口公开是设计。
- 找"会话感知"铁证：响应中出现 `is_login`、`is_collect:"未登录"` 这类字段 → 服务端能区分登录态却不拦截 = 设计给登录用户、漏鉴权，漏洞成立。
- 兄弟接口对照实验：同模块其他接口返回 401/403 而本接口放行 → 访问控制不一致，漏洞成立。
- 仅凭"业务功能应该登录"的断言不构成证据。

### 1.3 凭据可达问：攻击链依赖的凭据真的能到达攻击位置吗？
- 跨域/钓鱼链要求浏览器自动携带凭据。`credentials:'include'` 只带 Cookie/HTTP 认证/客户端证书，**永远不带 localStorage/sessionStorage 里的 token**。
- 若目标用 localStorage JWT + Authorization 头（查前端 JS 里的 `getToken`/`localStorage`），跨域链不成立。
- 若用 Cookie：检查 SameSite 属性。现代浏览器默认 Lax，跨站请求不携带；除非显式 `SameSite=None; Secure`。
- 审计方法（均可匿名做）：读目标前端 JS 产物确定 token 存储方式；抓响应的 `Set-Cookie` 看 SameSite。

## 2. 证据三级与危害四层

### 证据三级（报告每条危害必须标一级，且级别与事实相符）
| 级别 | 定义 | 审核权重 |
|---|---|---|
| 实测 | 发出了请求、拿到可归因的差异响应、有原始报文+带时间截图 | 唯一算数 |
| 推演 | 基于实测前提的合理威胁链，必须明确标注"未实施" | 辅助，不能当主危害 |
| 声称 | "可能/理论上/或许" | 零分，出现即提示删除 |

**纪律：定级必须锚定【实测】，【推演】只能作为上限注记。** 推演撑主向量是驳回和失信的最大来源。

### 危害四层（判断"危害是否够"的标尺）
- L0 存在性：接口存在、报错、指纹 → 不构成漏洞
- L1 可控性：能控制服务端行为（文件落盘、内容回显）→ 低危
- L2 数据/权限触及：读到敏感数据、越权操作、他人身份 → 中危起点，审核及格线
- L3 系统控制：RCE、凭据泄露、账户接管 → 高危
- L4 规模化影响：批量用户、核心业务、资金 → 高危/严重

"无明显敏感信息或进一步利用证明"这类驳回 = 证据停在 L1。要么沿升级路径打到 L2，要么如实接受低危，要么放弃。

## 3. 范畴错误与技术逻辑陷阱清单

逐项排查，命中即出具"严重问题"：

1. **CORS 对零认证端点零增量**：端点无需认证即可直接 curl，CORS 放行对它不产生额外危害。CORS 的危害增量只在"依赖浏览器环境凭据的端点"上成立。零认证端点应归入"未授权访问"自己的报告。
2. **凭据携带机制误判**：见 1.3。报告写"浏览器自动携带 Cookie/sessionStorage token" = 技术错误，sessionStorage/localStorage 永不被自动携带。
3. **302 只证明过了第一关**：OAuth /authorize 接受恶意 redirect_uri 返回 302 进登录页，不证明签发 code 时无第二次校验。闭环方法（合规）：自有域名配置前缀子域 + 自有测试账号完成登录，看 code 是否落到自有服务器日志；再测 PKCE 是否强制、state 是否强制、response_type=token 是否接受。无自有账号则停步并如实标注。
4. **UUIDv1 泄露指纹**：文件 URL 中 UUID 第三段以 1 开头 = v1，内嵌服务器 MAC 与精确时间戳。可用于核对报告时间线一致性（复现时间 vs UUID 时间戳），也可作为附加发现。
5. **公开数据当泄露**：见 1.1。
6. **WAF/CDN 行为当漏洞**：拦截页、缓存差异、负载均衡轮询造成的差异不可归因于漏洞。需对照组排除。
7. **扫描器输出当实测**：工具输出必须手工报文复打，否则标"疑似"。
8. **夸大危害等级参数**：C:H/I:H 只在真的读到/改到高价值数据时使用；个人信息通常 C:L；纯只读泄露不得带 I。
9. **同系统多洞混报**：一洞一报，但可交叉引用同系统其他报告的提交编号互相印证。

## 4. 语言黑名单（AI 痕迹词与术语错误）

发现即要求替换：

| 错误/痕迹 | 正确 |
|---|---|
| 黑客（全文） | 攻击者 |
| 认证权码 / 接收代码 / 权码 | 授权码（authorization code） |
| 黑室 | 黑盒 |
| 强弹 / 强弹性 | 劫持重定向 |
| 反向验证缺陷 | 重定向校验缺陷（CWE-601） |
| 交付值 / 主动交付 | 提交值 / 需诱导 |
| 主机头骗解析 | URL userinfo 欺骗（@后为真 host） |
| 可能严重 / 致命 / 核弹级 等情绪词 | 删除，只用档位词 |
| 按任务给定 / 综上所述本次任务 / 作为AI | 元语言，全部删除 |
| 绿色锁标 | 有效 TLS 证书（浏览器早已不显示绿色锁） |
| 算术上合法 / 标准打法 | 数值上成立 / 通用评分方式 |

## 5. 机械性硬伤清单

逐项 grep 检查：
1. **本地路径**：`C:\`、`/Users/`、`/home/`、`Desktop` —— 出现即删，改附件名。
2. **元语言**：提到"任务""提示词""重交稿（此前提交未通过）"等过程性文字 —— 删除；重交上下文写平台留言栏，不进正文。正文自标"曾被驳回"≈ 主动申请按重复驳回。
3. **占位符残留**：`[截图`、`待填`、`XXX`、`TODO`、空表格单元格。
4. **截图引用缺失**：每个复现步骤必须有【图 NN】标注 + 文末附件清单表，且图注与图内容一致。
5. **系统性缺字**：AI 生成/格式转换常丢字（"内网"→"网"、"其他"→"它"、"非必要字段"→"非字段"）。发现一处即要求全文通读校对。
6. **时区混用**：同系列报告统一时区（建议 CST）。HTTP Date 头天然 GMT，正文引用需换算一致。相邻测试时间的两份报告不得出现矛盾标注。
7. **厂商未响应谬误**：平台初审未通过 = 报告未到厂商。不得写"提交后厂商未修复/未响应"；只能写"距首次发现 N 天复测仍存活"。
8. **测试 UA 与平台不符**：如用 `EduSRC-...` UA 测补天目标。

## 6. 跨报告与内部一致性检查

同一资产/同系列报告必须核对：
1. **归属证据一致**：ICP 备案号、WHOIS 表述在所有报告中逐字一致；以工信部备案系统/官网页脚实抓为准。.edu.cn 主域 WHOIS 走 whois.edu.cn。
2. **定级口径一致**：A 报告说"同系统 B 洞为高危"，B 报告就不能定严重。
3. **时间线一致**：复现时间、UUID 内嵌时间戳、文件名在各步骤间自洽（同一轮测试的产物）。
4. **平台信息正确**：EDUSRC = src.sjtu.edu.cn（上海交大运营），不存在 edu.csrc.gov.cn。
5. **端点死活一致**：声称"受影响端点"的，正文不能又写它已 404；证据引用的页面路径需可打开。
6. **响应头细节**：`Allow` 头出现 PUT/DELETE 值得一次无害探测；`Set-Cookie` 的 SameSite 属性决定跨域链死活。

## 7. 合规红线

审核建议不得引导用户越过以下任何一条；报告违反即标"致命问题"：
1. 不拖库：样本数据取几条脱敏即止。
2. 不改数据：写入验证只用自建测试账号。
3. 不种马、不部署真实钓鱼页、不回传真实凭据。
4. 不批量/高频请求；不扫端口；不爆破（弱口令少量尝试不锁号）。
5. 偷来的凭据只证明存在，绝不登录使用（用了即违法）。
6. RCE 止于无害标记（echo/id），不提权、不内网、不留后门。
7. 合规闭环特权：仅"自有账号 + 自有域名 + 自有服务器"的链路允许走完整攻击流。
8. 保密纪律：修复完成前不公开细节（CVE 申请除外，它是最后一站）。
