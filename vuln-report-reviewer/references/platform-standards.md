## 1. 平台路由决策树

投错平台是最高频死因，先路由再评审：

- 教育行业资产（学校/教育局/教科网，备案主体为教育单位）→ **EDUSRC**（src.sjtu.edu.cn）
- 通用软硬件产品漏洞（同一产品有 ≥10 个互联网案例、开发商注册/实缴资本 ≥5000 万）→ **CNVD 通用型**（修复后可补 CVE）
- 党政机关/运营商/央企/重要行业单位的具体系统事件 → **CNVD 事件型**（仅高危发证）
- 企业资产（厂商在补天有项目或活跃认领）→ **补天**；冷门/停止维护厂商改道 CNVD/EDUSRC
- 公开可得的开源/商业软件、要国际编号、接受最终公开 → **CVE**（永远最后一站）
- 单一定制系统（只为一家开发部署）→ 不要去 CVE；走 SRC/CNVD 事件型

## 2. EDUSRC 标准

- 官方地址 **src.sjtu.edu.cn**（上海交通大学运营）。不存在 edu.csrc.gov.cn，写错地址一切免谈。
- 收录：教育部、教育厅/局、各级各类学校资产漏洞；威胁情报（被入侵/挂灰链）也收。
- 定级：Rank 0–10；严重 [9,10]、高危 [7,9) 、中危 [4,7)、低危 [0,4)。
- 类型口径参考：高危 = RCE/webshell/任意改密/批量身份盗取/绕认证进后台/管理员弱口令；中危 = 条件受限的权限获取、任意文件读写删下载、水平越权改资料；低危 = 非核心数据、条件苛刻、需交互的 XSS/CSRF。
- 流程：审核约半个月，严重优先；Rank + 金币，金币兑换证书/礼品。
- 铁律：提交后禁止公开漏洞细节。

## 3. 补天标准

- 状态机：待审核 →（待补充 / 审核不通过 / 审核通过）→ 厂商确认 → 奖金确认 → 周三打款。
- 官方初审五大不通过：①无法复现 ②危害小 ③抄袭或未经验证的提交 ④无法联系厂商/厂商太小/停止维护 ⑤重复或细节已公开。
- 厂商侧三种忽略：误归属、重复、无影响。
- 周期：公益 SRC 审核后约 7 天等厂商认领，无人认领平台确认转监管；专属 SRC 厂商一周内复审，超期默认通过。
- 要点：POC+截图+链接齐全否则进"待补充"；提交前查厂商活跃度；重复提交/低质提交影响账号权重。

## 4. CNVD 标准

- 分两类：**事件型**（某单位具体系统）与**通用型**（通用产品）。
- 三级审核：一审完整性（可验证+描述无虚假）→ 二审整理 → 三审有效性复现 + 原创性全网查重 → 归档。
- 发证硬门槛（达不到 = 归档无证书）：
  - 通用型：中危及以上（CVSS2.0 基准 >4.0）+ 开发商注册（实缴）资本 ≥5000 万 + 互联网案例 ≥10（至少 3 个复现成功，建议 5 个；或代码审计路线免案例）
  - 事件型：三大运营商中高危，或党政机关/重要行业/科研院所/央企等高危
- 周期：事件型 ≤1 工作日验证、≤3 工作日通报；通用型 ≤5 工作日通报厂商；归档后周三周四批量制证；催办发 vreport@cert.org.cn 附编号。
- 暗坑：单位性质模糊会被"暂不归档"（先用 ICP+企业信用信息核实性质）。

## 5. CVE 标准

- 性质：MITRE 主导的全球漏洞编号体系，由 CNA 分配；不是奖励平台，不打分。
- 分配三条件：①有合理证据 ②已公开或预期将公开 ③在该 CNA scope 内。
- 红线：不分配给从未公开发售的产品；分配后必须公开，否则 REJECT；单一服务/网站漏洞（service-only）不收。
- 个人路径：cveform.mitre.org 全英文；先查厂商是否 CNA 成员（是则报该 CNA）；先搜历史 CVE 防重复；周期约 1 个月。
- 材料：漏洞类型、vendor/product/version 精确、英文分析文（博客/GitHub issue）作参考链接。

## 6. 一洞多投顺序纪律

私密修复渠道（EDUSRC/补天/CNVD/厂商）→ 修复后公开渠道（CVE/博客）。顺序反了两头都废：SRC/CNVD 要求修复前保密且查重看互联网公开情况，CVE 要求最终公开。同系统多洞：一洞一报，交叉引用提交编号。

## 7. 驳回理由总字典

| # | 驳回语 | 真实原因 | 处方 |
|---|---|---|---|
| 1 | 非收录范围/误归属/暂不归档 | 路由错误或单位性质不认定 | 归属证明补齐；单位性质 ICP+工商信息佐证；仍不收换平台 |
| 2 | 重复漏洞/已有记录 | 别人先交或同源已收录 | 提交前查重（平台内+Google+CVE+CNVD库）；撞洞不可补救，换资产 |
| 3 | 无法复现/待补充/细节过简 | 报文不全、前置条件没写、无图 | 补完整报文文本+每步截图+前置条件+录屏，复现 3 次再交 |
| 4 | 危害不足/无敏感信息/影响不大 | 证据停在 L1 未到 L2 | 沿升级路径补打（越权/读配置/桶列举）；补不到接受低危或弃；切勿夸大 |
| 5 | 疑似扫描器/未经验证 | 只有工具输出 | 全部手工报文复打，加对照组 |
| 6 | 抄袭/互联网已公开 | 细节被公开过（含自己发的） | 无补救；修复前零公开 |
| 7 | 原创性核验失败（CNVD 三审） | 全网查重不过 | 同 2/6；CNVD 必须首交且零公开 |
| 8 | 案例不足/资本不足（CNVD 通用型） | 硬指标没到 | 补案例至 10+（5 个最小化复现）；资本不足改投 EDUSRC/补天 |
| 9 | 厂商不认领/停止维护（补天） | 厂商侧问题 | 等满 7 天平台确认转监管；下次先看厂商活跃度 |
| 10 | CVE 拒绝：非产品漏洞/不公开/找错 CNA | 定制单站/保密/入口错 | 单站别申请；接受公开再申请；先查 CNA 成员表 |
| 11 | 公开数据不算泄露 | 数据本就在官网/公开渠道 | 证明接口返回超出公开范围；证明不了就放弃 |
| 12 | 设计使然的公开功能 | 匿名页面本就展示该数据 | 找会话感知字段/兄弟接口 401 对照；找不到就放弃 |
